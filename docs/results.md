## 2. Barge-in: how fast does the agent stop?

Each caller speaks, lets the agent talk for 0.6 s, then talks over it. *Cut-off* is the time from the start of the interruption to the gateway telling the client to stop. *Stale frames* counts agent audio that still arrived after the stop signal (must be 0).

| Sessions | Cut-off p50 ms | p95 | p99 | Stale frames | Failed rounds | Speech never heard (sent to TTS) | Text never heard (written by LLM) | Valid |
|---|---|---|---|---|---|---|---|---|
| 20 | 142 | 146 | 154 | 0 | 0 | 39% | 39% | yes |

The cut-off is dominated by a deliberate guard: while the agent is talking, the gateway needs 8 voiced frames out of the last 10 (about 160 ms of audio) before it treats a sound as an interruption, so noise and "mm-hmm" do not cut the agent off. The caller's clock starts at the first speech frame, so the 8th voiced frame arrives about 140 ms later; the remainder is the gateway's own reaction time. The last two columns are large by design in this scenario: the caller interrupts 0.6 s into a reply that is several seconds long, and a fast LLM has usually finished writing before the caller hears the first word. Cancelling saves the speech synthesis and the playback, not much LLM work.
